Project Overview

BankFlow is a full-stack, enterprise-grade banking system built on microservices architecture. It simulates the core functionality of a modern digital bank: customer registration, account management, fund transfers, loan processing, and transaction fraud detection — all with a React web dashboard.

What Does BankFlow Do?

  • User Management: Customer registration with phone validation, JWT login, KYC verification, admin role management
  • Account Management: Open SAVINGS/CURRENT/FIXED_DEPOSIT accounts, balance inquiry, freeze/unfreeze
  • Transactions: Deposit, Withdraw, Fund Transfers via IMPS/NEFT/RTGS/UPI with real-time Kafka events
  • Loan Processing: Apply for 6 loan types, EMI calculation, amortization schedule, admin approval workflow
  • Fraud Detection: Rule-based risk scoring on every transaction, automatic alert generation
  • Notifications: Kafka-driven email/SMS alerts for every banking event
  • React Dashboard: Full-featured web app for all banking operations

Microservices Breakdown

🌐 API Gateway (:8080)

Single entry point for all client requests. Routes to downstream services based on path prefix. Validates JWT tokens and applies circuit breakers. Configured with CORS for the React frontend.

  • /api/auth/**, /api/users/** → User Service (:8081)
  • /api/accounts/** → Account Service (:8082)
  • /api/transactions/** → Transaction Service (:8083)
  • /api/loans/** → Loan Service (:8084)
  • /api/fraud/** → Fraud Detection (:8086)

👤 User Service (:8081)

Handles all authentication and user management. The User entity implements Spring Security's UserDetails interface. Publishes user.registered event to Kafka on new registrations.

  • User entity with userId, email, phone, role, kycStatus
  • Roles: CUSTOMER, ADMIN
  • KYC Status: PENDING → UNDER_REVIEW → VERIFIED | REJECTED
  • Swagger UI: http://localhost:8081/swagger-ui.html

🏦 Account Service (:8082)

Manages bank accounts with real-time balance tracking. Generates 16-digit account numbers with duplicate checking. Provides debit/credit operations with @Transactional for atomicity.

  • Types: SAVINGS, CURRENT, FIXED_DEPOSIT, RECURRING_DEPOSIT
  • Status: ACTIVE, INACTIVE, FROZEN, CLOSED
  • IFSC Code: BNKF0001234 | Currency: INR
  • Admin can freeze/unfreeze accounts

💸 Transaction Service (:8083)

Processes all financial movements. Every transaction publishes to Kafka for notifications and fraud checking. Supports pagination for transaction history.

  • Types: DEPOSIT, WITHDRAWAL, TRANSFER_DEBIT, TRANSFER_CREDIT, LOAN_DISBURSEMENT
  • Modes: IMPS (instant), NEFT (batch), RTGS (high value), UPI, CASH, ATM
  • Publishes to: transaction.created, transfer.initiated, fraud.check.request

💰 Loan Service (:8084)

Full loan lifecycle management. Calculates EMIs using the standard formula and generates an amortization table with principal and interest breakdown per installment.

  • Types: PERSONAL (12%), HOME (8.5%), VEHICLE (9.5%), EDUCATION (7.5%), BUSINESS (14%), GOLD (10%)
  • Status: PENDING → APPROVED/REJECTED → DISBURSED → CLOSED
  • EMI Formula: P × r × (1+r)^n / ((1+r)^n - 1)

🔔 Notification Service (:8085)

Kafka consumer that listens on 7 topics and sends email/SMS notifications. Stateless — no database needed.

Listens to: user.registered, transaction.created, transfer.initiated, loan.approved, loan.rejected, account.created, fraud.alert

🚨 Fraud Detection Service (:8086)

Rule-based fraud analysis. Scores every transaction and creates alerts when risk exceeds threshold. Publishes fraud alerts to Kafka.

  • Rule 1: Amount > ₹5 Lakh → +40 points
  • Rule 2: Amount > ₹1 Lakh → +20 points
  • Rule 3: WITHDRAWAL or TRANSFER → +10 points
  • Rule 4: Round number (multiple of ₹10,000) → +5 points
  • Score ≥ 30 → Create MEDIUM_RISK alert | Score ≥ 60 → HIGH_RISK alert

Kafka Event-Driven Communication

All inter-service communication happens asynchronously via Apache Kafka. Services are fully decoupled — they never call each other directly.

user.registeredProducer: User Service → Consumer: Notification
account.createdProducer: Account Service → Consumer: Notification
transaction.createdProducer: Transaction Service → Consumer: Notification, Fraud
transfer.initiatedProducer: Transaction Service → Consumer: Notification, Fraud
fraud.check.requestProducer: Transaction Service → Consumer: Fraud Detection
fraud.alertProducer: Fraud Detection → Consumer: Notification
loan.appliedProducer: Loan Service → Consumer: Notification
loan.approvedProducer: Loan Service → Consumer: Notification
loan.rejectedProducer: Loan Service → Consumer: Notification
loan.disbursedProducer: Loan Service → Consumer: Notification, Transaction

💡
Interview Answer: "I use Redis in BankFlow for three main purposes: (1) JWT blacklist — when a user logs out, the token is added to Redis with the remaining expiry as TTL, so invalidated tokens are blocked. (2) Account balance caching — balance queries are very frequent; caching for 60 seconds reduces database load significantly. (3) OTP storage — 5-minute TTL ensures OTPs expire automatically without any cleanup job."

Security Architecture

JWT Authentication Flow

1. POST /api/auth/login {email, password}
2. AuthenticationManager validates BCrypt(password) against stored hash
3. JwtService.generateToken() → HS256 signed JWT (24h expiry)
4. Token returned to React → stored in localStorage
5. Every subsequent request: Authorization: Bearer [token]
6. JwtAuthenticationFilter (OncePerRequestFilter):
   a. Extract token from "Bearer " prefix
   b. Decode and validate signature using secret key
   c. Check expiry
   d. Load user from DB by email
   e. Set auth in SecurityContextHolder
7. @PreAuthorize("hasRole('ADMIN')") enforced by Spring Security

Fraud Detection Engine

Every transaction triggers a fraud check request via Kafka topic fraud.check.request. The Fraud Detection Service applies 4 rules and assigns a risk score:

RuleConditionRisk Points
Large TransactionAmount > ₹5,00,000+40
High-Risk AmountAmount > ₹1,00,000+20
Debit TransactionType = WITHDRAWAL or TRANSFER+10
Round NumberAmount is multiple of ₹10,000+5

If riskScore ≥ 30: creates a FraudAlert record (MEDIUM_RISK or HIGH_RISK) and publishes to fraud.alert Kafka topic, which triggers a Notification Service alert.

Interest Rates by Loan Type

Loan TypeAnnual RateMax TenureUse Case
PERSONAL12.00%60 monthsGeneral purpose

GOLD10.00%24 monthsGold collateral

EMI Formula

EMI = P × r × (1 + r)^n / ((1 + r)^n − 1)

Where:
  P = Principal loan amount
  r = Monthly interest rate = Annual rate / 12 / 100
  n = Tenure in months

Example: ₹5,00,000 Personal loan at 12% for 36 months
  r = 12 / 1200 = 0.01
  EMI = 500000 × 0.01 × (1.01)^36 / ((1.01)^36 − 1)
      = ₹16,607.15/month

CI/CD Pipeline (Jenkins)

7-stage declarative pipeline defined in Jenkinsfile:

  1. Checkout — Pull latest code from Git
  2. Build — Compile all 6 backend services with Maven
  3. Unit Tests — Run JUnit tests, publish Surefire reports
  4. Package — Create executable JAR files
  5. Docker Build — Build 8 Docker images (7 services + frontend)
  6. Docker Push — Push to registry (main branch only)
  7. Deploy — docker-compose up -d on target environment

How to Run

🐳 Docker Compose (Recommended)

cd bankflow
docker-compose up --build
# Wait 5-10 minutes for first run
# Frontend: http://localhost:3000
# API:      http://localhost:8080
# Swagger:  http://localhost:8081/swagger-ui.html

Test Login

curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@bankflow.com","password":"Admin@123"}'

Open an Account

curl -X POST http://localhost:8080/api/accounts \
  -H "Authorization: Bearer [TOKEN]" \
  -H "Content-Type: application/json" \
  -d '{"accountType":"SAVINGS","branch":"Main Branch"}'

Apply for Loan

curl -X POST http://localhost:8080/api/loans/apply \
  -H "Authorization: Bearer [TOKEN]" \
  -H "Content-Type: application/json" \
  -d '{"loanType":"PERSONAL","amount":500000,"tenureMonths":36,"accountNumber":"XXXX"}'
